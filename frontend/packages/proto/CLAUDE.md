# CLAUDE.md — @frontend/proto

Guidance for working inside `frontend/packages/proto`. The cross-service contract flow and the three generated proto flavors are documented in the root `CLAUDE.md` _Protobuf codegen pipeline_ section — read that first.

## What this is

The **fully generated** frontend gRPC client package — the Client flavor of `packages/proto/pkg`. Its `src/` (including `src/index.ts`) is generated by this package's own `compiler/`: the Client adapter, its transform tasks (`FixClientExportsTask`, `AddClientRepositoriesTask`) and Pug template, running on the shared core `@packages/proto/compiler`. The core's internals are in `packages/proto/CLAUDE.md`.

Every file under `src/` is emitted by `protoc-gen-ts_proto` and carries `// @ts-nocheck`, `DO NOT EDIT`, `/* eslint-disable */`. Never hand-edit it; the whole tree is wiped and regenerated on each compile.

> **Why the Client adapter lives here:** [docs/adr/0023-proto-codegen-task-per-package.md](../../../docs/adr/0023-proto-codegen-task-per-package.md)

## How to (re)generate

Edit the `.proto` source in `packages/proto/pkg/**`, then from the repo root run `pnpm compile:proto` (all three targets) or `turbo run compile --filter=@frontend/proto` (this one; it builds `@packages/proto` first). Commit the rewritten `src/`. The turbo `compile` task outputs `src/**` and takes `.proto` edits through the hash of `@packages/proto#compile`, not as its own input.

## What it exports (`src/index.ts`)

- Message namespaces, `Client`-prefixed: `ClientAuth`, `ClientCommon`, `ClientStorage`, `ClientGoogle` (vs. the `Nest*` namespaces in `@backend/proto`).
- Per-service **client repositories**: `Grpc<X>Repository` plus `Grpc<X>Admin/Web/PublicRepository` (e.g. `GrpcUserRepository`, `GrpcUserAdminRepository`). These are the frontend equivalent of backend Transports — the admin app talks to api-gateway through them.

Messages use `@bufbuild/protobuf/wire` (`BinaryReader/Writer`, `encode`/`decode`/`fromJSON`/`fromPartial`); service stubs use `@grpc/grpc-js`. Depends on `@packages/proto` (workspace). The compiler's own needs are devDependencies: `ts-proto` (its `protoc-gen-ts_proto` binary in this package's `node_modules/.bin` is the plugin protoc runs), `ts-morph`, `change-case-all`, `tsx`.

## Commands

```bash
pnpm compile          # tsx compiler/main.ts → regenerates src/ (needs protoc and a built @packages/proto)
pnpm build            # prettier src (silent) → tsdown → dist (esm + cjs + d.ts)
pnpm dev              # tsdown --watch (build only — does NOT regenerate from .proto)
pnpm typecheck        # tsc --noEmit over src + compiler (strict — the compiler code too)
pnpm format           # prettier src
pnpm reset            # rm -rf .turbo dist node_modules
```

Note `build` formats before bundling (unlike sibling packages where `format` is separate). Consumers resolve `dist/`, so rebuild after a regenerate; turbo's `^build` handles this for downstream apps.

## Consumers & gotchas

- Sole consumer: `frontend/apps/admin`.
- Change contracts in `packages/proto/pkg`; fix generated-code bugs in this package's `compiler/` (or the shared tasks in `packages/proto/compiler`), never in the output here.
- Don't add runtime logic to `src/` — `compiler/` is the only hand-written code here; anything else belongs in the admin app or a real shared package.
